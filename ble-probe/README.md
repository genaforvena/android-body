# BLE capability diagnostic

Separate application ID `org.androidbody.bleprobe`; never upgrades or shares the Android Body package/data. Min API 18. The UI and self-targeted `ProbeInstrumentation` use the same `CapabilityReport` collector. It reports SDK, adapter state, and (API 21+) scanner/advertiser accessor availability and multiple-advertisement support. It does not start discovery, scan, advertise, toggle Bluetooth, inspect device identities, persist data, or use the network.

Run the instrumentation with `am instrument -w -e run_id NONCE org.androidbody.bleprobe/.ProbeInstrumentation`; use only a safe single-line nonce matching `[A-Za-z0-9_-]{1,64}`. The result includes `run_id`, terminal `status`, and base64 UTF-8 `report_b64`, keeping multiline report data safely framed in the instrumentation stream. The JVM classifier rejects missing or malformed run IDs, another run, non-complete status, oversized/partial/duplicate-key/unknown-key reports, blank values, wrong source, and invalid SDK/timestamp syntax. Explicit `error:` and `not_tested` query values remain observations, not proof of successful capability. Age is caller-supplied and bounded to 0–60 seconds; this module does not parse the instrumentation terminal stream or bind age to host receipt time. Device time and clock synchronization remain UNKNOWN until a consumer validates one successful terminal result and records its monotonic receipt.

`OFF` and null scanner/advertiser accessors are conditional-unavailable, not unsupported. Object availability is not proof of over-air capability. Errors and API<21 queries are explicitly reported. `sampled_at_utc` is the device wall clock, not host-correlated freshness. Do not save result output in shared logs or sensor history. Keep these manual diagnostic readings out of `watch.py`.

Build and run the formatter regression test with JDK 11+ and Android SDK platform 34: `./gradlew --no-daemon :ble-probe:testProbeReport :ble-probe:assembleDebug :ble-probe:lintDebug`. The app targets API 28 intentionally for local diagnostics on legacy API18–21 hardware; it is not for Play distribution. Lint disables only the expired target and newer-compile-SDK policy checks for that bounded use.

Do not install unless signer/data preservation and a bounded cleanup route have been independently reviewed. No Note3 runtime result is implied by building the APK.
